# 4단계 · 스코어카드

**배점은 자체 기준이다. 업계 절대 등급이 아니다.** 리포트에 그렇게 적는다.
쓸모는 하나 — 흩어진 측정치를 **어디를 먼저 고칠지** 한 장으로 정렬하는 것.

## 구조

시청을 결제로 바꾸는 조건을 4층으로 나누고 층마다 25점씩 균등 배점한다.

| 층 | 질문 | 항목 (배점) |
|---|---|---|
| **A 트래픽 품질** | 유입이 살 사람인가 | A1 구매전환율(10) · A2 유입–구매 정합성(8) · A3 실참여자 비율(7) |
| **B 결제 경로** | 사고 싶을 때 살 수 있나 | B1 인앱 결제(10) · B2 홉 수(8) · B3 게스트 결제(7) |
| **C 상품 적합성** | 라이브에서 팔릴 물건인가 | C1 충동가격대 비중(10) · C2 매출 분산(8) · C3 사이즈 커버리지(7) |
| **D 방송 운영** | 파는 행위를 하고 있나 | D1 진행자 응대(9) · D2 시간 활용(8) · D3 VOD 롱테일(8) |

## 입력

`make_measures.py` 가 `runs.json` 에서 자동으로 채워 준다 — 조회수·구매자·참여자 합계,
순위상관 `view_buy_rho`(스피어만, 동점은 평균 순위), 죽은 구간 평균, 상위3품목 평균,
그리고 회차 날짜가 있으면 진행자 응대 코호트(`seller_chat_now`/`_peak`)까지.

```bash
python3 scripts/make_measures.py runs.json -o measures.json
```

**채팅에 없는 값은 `_todo` 로 남는다** — 퍼널 홉 수, 인앱/게스트 결제, 가격대 비중,
사이즈 커버리지, VOD 롱테일. 전부 1단계에서 직접 확인해야 하는 것들이다.
빠진 채로 채점하면 `scorecard.py` 가 무엇이 없는지 알려주고 멈춘다.

```json
{
  "views": 422400, "buyers": 1536, "participants": 1330,
  "view_buy_rho": -0.882,
  "inapp_checkout": "none",
  "hops": 4, "hop_path": ["youtube", "인포크링크", "fple.live", "카카오 로그인", "주문"],
  "guest_checkout": "signup_required",
  "impulse_price_share": 2.2, "top3_share": 56.8, "size_coverage": "one_plus",
  "seller_chat_now": 130, "seller_chat_peak": 593,
  "dead_ratio": 52.3, "vod_longtail": "recent_few"
}
```

열거형 값:
- `inapp_checkout`: `full` / `partial` / `none`
- `guest_checkout`: `guest` / `social_1tap` / `signup_required` / `app_required`
- `size_coverage`: `broad` / `two` / `one_plus` / `single`
- `vod_longtail`: `all` / `30d` / `recent_few` / `live_only`

구간 임계값은 `scripts/scorecard.py` 의 `score()` 안에 표로 들어 있다. 카테고리가
다르면(예: 식품 라방) 임계값을 조정하되, **조정했다는 사실을 리포트에 적는다.**

## 세 종류의 점수를 갈라 읽는다

스크립트가 세 덩어리로 나눠 출력한다. 이 구분이 처방의 뼈대다.

1. **자체 실행 여지** — 셀러가 지금 당장 손댈 수 있는 항목. 처방은 여기서만 나온다
2. **플랫폼 구조 의존**(B1·B3) — 인앱 결제·게스트 결제. 자체로 닫을 수 없다.
   **닫을 수 없다고 솔직히 쓰는 것**이 오히려 나머지 처방의 실행력을 높인다
3. **결과지표 연동**(A1·A3) — 다른 항목이 오르면 따라 오른다. **처방 합계에서 중복
   계산하지 않는다.** 여기서 이중계산하면 기대효과가 뻥튀기되고 3개월 뒤 신뢰를 잃는다

## 목표점은 따로 잡는다 — 만점을 목표로 두지 않는다

스크립트의 "자체 실행 여지"는 **이론상 최대**다. 그대로 제안서에 쓰면 안 된다.
항목별로 3개월 내 현실적인 목표점을 직접 잡고 합산한다.

원 사례: 이론상 여지 +53 → 7개 항목에 목표를 잡아 **+28 (18점 → 46점)** 로 제출.

| 실행 항목 | 대상 | 현재 → 목표 | 가산 |
|---|---|---|---|
| 2~5만원대 상품 10개 편성 | C1 | 1 → 6 | +5 |
| 지난 회차 상시 판매 페이지 | D3 | 1 → 7 | +6 |
| 방송 270~300분 단축 | D2 | 2 → 6 | +4 |
| 셀러 채팅 응대 복원 | D1 | 2 → 6 | +4 |
| 1일 2회 타겟 분할 | A2 | 1 → 5 | +4 |
| 로그인 선행 유도 | B2 | 1 → 4 | +3 |
| 회차당 주력 품목 분산 | C2 | 3 → 5 | +2 |

이 표를 그대로 리포트 1장 하단에 넣는다. **점수가 처방으로, 처방이 실행 항목으로
이어지는 경로가 한 장에 보이는 것**이 이 스코어카드의 전부다.

## 회귀 검증

```bash
python3 scripts/scorecard.py --example   # 18/100 이 나와야 정상
```

임계값을 손봤으면 이 검증이 깨진다. 의도한 변경이면 `EXAMPLE` 의 기대값도 같이
고치고, 왜 바꿨는지 커밋 메시지에 남긴다.
