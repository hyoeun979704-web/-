# 5단계 · 리포트 집필

산출물은 **아티팩트 한 장**이다. `assets/report-skeleton.html` 을 복사해 채운다.
디자인 시스템을 새로 짜지 않는다.

## 12장 구조

순서에 의미가 있다. **증거 → 원인 → 처방 → 한계** 순이고, 셀러가 위에서부터
읽다가 어디서 멈춰도 그 지점까지는 완결되게 짜여 있다.

| 장 | 내용 | 빠지면 안 되는 것 |
|---|---|---|
| 머리 | 판정문(verdict) | 셀러가 실제로 물은 질문에 대한 **한 문장 답** |
| 〃 | 3분 요약 | 한 줄 / 확인된 것 / 왜 / 무엇부터 / 기대효과 — 5행 |
| 01 | 전환 스코어카드 | 점수 + 실행 항목 표 |
| 02 | 결정적 증거 | 회차별 1천뷰당 구매자 — **가장 강한 한 장을 여기 둔다** |
| 03 | 대조 | 유형별 투입 조회수 vs 산출 구매자 |
| 04 | 가격 구조 | 가격대 분포 + 사이즈 커버리지 |
| 05 | 참여 붕괴 | 첫20분 집중도 · 죽은 구간 · **채팅/주문 시간축 겹침** |
| 06 | 전수 표 | 회차별 전 지표. 영상 ID 포함(재현용) |
| 07 | 원인 | 6개 내외. 각 항목에 **증거 한 줄** 첨부 |
| 08 | 편성 재설계 | 분당 주문 수 기반 구조 제안 |
| 09 | 솔루션 | 처방. 각 항목에 담당·시점·확인지표 |
| 10 | 벤치마크 | 동급 채널 대조 + 등급 카드 |
| 11 | 트래킹 | **이 보고서가 답하지 못하는 것** |
| 12 | 방법 | 출처·규모·검증법·틀릴 수 있는 지점 |

## 집필 규칙

**모든 장에 "쉽게 말하면" 블록을 단다.** 셀러는 데이터 분석가가 아니다. 본문은 분석
언어로 쓰되, 각 장 첫머리에 한 문단으로 평이하게 다시 쓴다. `.plain` 클래스.

```html
<p class="plain"><b>쉽게 말하면</b> — 사람이 많이 본 방송일수록 오히려 산 사람
비율이 낮았습니다.</p>
```

**용어 풀이를 넣는다.** "1천뷰당 구매의사 발화", "죽은 시간대 비율", "홉" 같은 자체
조어는 9장 끝에 `.gloss` 로 풀어둔다.

**숫자에는 항상 분모를 붙인다.** "57%"가 아니라 "전체 채팅 128,189건 중 57%".

**처방에는 담당·시점·확인지표 세 개를 반드시 붙인다.** 확인지표가 없는 처방은
3개월 뒤 성패를 판정할 수 없고, 그러면 다음 계약이 없다.

```
담당: 저희 + 진행자   시점: 1주차   확인: "저요" 채팅 수 회차당 7건 → 100건 이상
```

**셀러가 준비할 것을 표로 뽑는다.** 리포트가 "저희가 다 하겠습니다"로 끝나면 실행이
안 된다. 상대가 줘야 할 것(데이터 권한·소싱·인력)을 시점과 함께 명시하고, **확보가
어려우면 뺄 수 있는 항목도 표시**한다.

**기대효과는 정직하게.** 1순위 벤치마크는 **목표가 아니라 상한**이라고 쓴다. 금액
데이터가 없으면 **매출 목표를 숫자로 약속하지 않는다** — 그 이유를 11장에 적는다.

## 디자인

`assets/report-skeleton.html` 에 전부 들어 있다.

- 신문 편집 톤 — 본문 `IBM Plex Sans KR`, 제목 `Gowun Batang`(명조), 숫자 `IBM Plex Mono` 탭러 정렬
- 색은 **2색만** — 대비되는 두 그룹(예: 고가/저가)에 각각. 강조색을 늘리지 않는다
- 차트는 **인라인 SVG 직접 생성**. 라이브러리를 넣지 않는다 (CSP·용량)
- 라이트/다크 양쪽 토큰을 `:root` / `prefers-color-scheme` / `[data-theme]` 3중으로 정의
- 표는 `overflow-x:auto` 래퍼 안에. 본문은 절대 가로 스크롤되지 않게

차트를 새로 그릴 일이 있으면 `artifact-diagramming` 스킬을 함께 읽는다.

## 발행

```
Artifact(file_path=..., title="<채널명> 라이브 진단", favicon="📉")
```

제목은 **채널명 + 진단**으로 짧게. 갤러리에서 식별되는 이름이어야 한다.
