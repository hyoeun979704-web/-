# 1단계 · 수집

공개 데이터만 쓴다. 셀러 계정 권한은 이 단계에서 요구하지 않는다 — 권한 없이
어디까지 보이는지가 곧 리포트의 설득력이다.

## 1.1 채팅 리플레이 (가장 중요)

유튜브 라이브 VOD는 채팅 리플레이를 통째로 보관한다. 여기에 **발화자·시각·주문
로그**가 전부 들어 있다. 이 스킬의 지표 대부분이 여기서 나온다.

```bash
# 회차 목록 뽑기 (라이브 탭)
yt-dlp --flat-playlist -J "https://www.youtube.com/@CHANNEL/streams" \
  | jq -r '.entries[] | [.id, .title, .view_count, .duration] | @tsv'

# 회차별 채팅 리플레이
yt-dlp --skip-download --write-subs --sub-langs live_chat \
       -o "chats/%(id)s.%(ext)s" "https://www.youtube.com/watch?v=VIDEOID"
```

`scripts/fetch_chat.sh` 가 위 두 단계를 묶어둔 것이다.

**조회수·길이는 채팅에 없다.** `-J` 메타데이터에서 따로 뽑아 `views.json` 으로 만든다.

```json
{ "oFbQvc2cc2o": { "views": 86400, "duration_min": 398, "title": "...", "kind": "고가" } }
```

`kind` 는 회차 성격 분류다(고가/저가 등). 3장 대조 분석의 그룹 축이 되므로 수집
시점에 회차 제목·썸네일을 보고 직접 붙인다. 애매하면 상품 카탈로그를 본 뒤 정한다.

### 주문 로그 파싱 — 채널마다 다르다

`scripts/analyze_chat.py` 상단 정규식을 **반드시 대상 채널 포맷에 맞춰 확인**한다.

| 정규식 | 무엇을 잡나 | 확인 방법 |
|---|---|---|
| `ORDER_RE` | 주문완료 봇 메시지 | 회차 하나에서 봇 발화를 눈으로 확인 |
| `BUYER_RE` | 마스킹된 구매자명 | `정*정님 주문완료!` → `정*정` |
| `ITEM_RE` | 상품코드/상품명 | 대괄호가 아닐 수 있음 |
| `INTENT_RE` | 구매의사 발화 | 벤치마크에도 **똑같이** 적용 |

정규식을 고쳤으면 회차 하나를 눈으로 대조해 검산한다. 여기서 틀리면 리포트 전체가
틀린다.

## 1.2 상품·가격 카탈로그

주문 페이지(피플라이브·스마트스토어·자사몰)에서 회차별 상품을 수집한다.
필요한 필드는 **이름 · 가격 · 옵션(사이즈) · 품절 여부 · 회차**다.

- 회차 선택자(드롭다운)의 `broadcastId` 를 바꿔가며 순회한다
- **몇 회차까지 남아 있는지 반드시 기록한다** — 지난 회차가 사라지면 그 자체가
  D3(VOD 롱테일) 항목의 감점 근거다
- 가격은 할인가 기준. 정가만 있으면 그렇게 명시한다

## 1.3 퍼널 동선 — 직접 따라간다

**시청자인 척 실제로 주문 직전까지 가본다.** 스크래핑으로는 안 나온다.

기록할 것:
1. **홉 수** — 화면이 바뀌는 횟수 (유튜브 → 링크 → 주문사이트 → 로그인 → 주문 = 4홉)
2. **로그인 요구 시점** — 진입 즉시인가, 결제 직전인가
3. **게스트 결제 가능 여부** — 회원가입 없이 끝나는가
4. **인앱 결제 여부** — 방송 화면 안에서 결제가 끝나는가
5. **미사용 기능** — 주문 페이지가 첫 화면에서 내세우는데 방송에선 안 쓰는 기능

5번이 처방 1순위가 될 확률이 높다. 플랫폼 첫 화면·도움말을 훑어볼 것.

## 1.4 수집 한계 기록

수집하면서 **못 얻은 것을 즉시 적어둔다.** 리포트 11장(트래킹)이 이 메모로 만들어진다.
전형적으로 빠지는 것: 주문 금액·객단가, 실제 동시접속자, 유입 소스, 단계별 이탈률,
재구매 비중(구매자명 마스킹 때문에 회차 간 동일인 추적 불가).
