# 2단계 · 지표

`scripts/analyze_chat.py` 가 계산한다. 정의는 아래와 1:1로 대응한다.
**모든 비율 지표는 조회수로 정규화**한다 — 채널 규모가 달라도 비교되게 하기 위해서다.

## 전환 지표 (주문 로그가 있어야 계산 가능)

| 지표 | 계산식 | 읽는 법 |
|---|---|---|
| `buyers` | 주문봇 메시지의 **유니크 구매자명** | 추정이 아니라 방송에 기록된 값 |
| `buyers_per_1k` | `buyers / views × 1000` | **회차 순위를 매기는 주력 지표** |
| `conv_pct` | `buyers / views × 100` | 전환율. 조회수는 누적이라 과소평가된다 |
| `orders_per_buyer` | `orders / buyers` | 1인당 몇 건 담는가 |
| `orders_per_min` | `orders / duration` | 회차 유형별 판매 속도. 편성 재설계 근거 |
| `top3_share_pct` | 상위 3품목 주문 / 전체 주문 | 100%면 그 회차는 상품 1~2개로만 판 것 |

## 참여 지표 (주문 로그 없어도 계산됨)

| 지표 | 계산식 | 읽는 법 |
|---|---|---|
| `participants_pct` | `유니크 발화자 / views × 100` | 실참여 밀도. 동접의 대리 지표 |
| `first20_share_pct` | 첫 20분 채팅 / 전체 채팅 | **가장 강력한 단일 지표.** 아래 참조 |
| `dead_ratio_pct` | 참여자 ≤10명인 10분 버킷 비율 | 방송이 얼마나 비어 있나 |
| `intent_per_1k` | 구매의사 발화 / views × 1000 | 벤치마크와 비교 가능한 유일한 전환 대리 지표 |
| `seller_rate_pct` | 진행자·모더레이터 채팅 / 전체 채팅 | 응대 밀도 |
| `jeoyo` | 플랫폼 선착순 주문 트리거 발화 수 | 미사용 기능 탐지 |

### `first20_share_pct` 가 왜 결정적인가

원 사례에서 이 값이 유일한 극단값이었다. 대상 채널 **57%**, 동급 6개 채널 **8~18%**.
방송 길이·조회수·구독자는 전부 무리 한가운데인데 이것만 3배 이상 벗어났다.

**"업계가 원래 그런 게 아니라 이 채널만 그렇다"를 증명하는 한 장**이 여기서 나온다.
벤치마크 없이 이 숫자만 보면 아무 의미가 없다는 점에 주의 — 반드시 3단계와 짝이다.

## 버킷 원자료

`buckets` 에 10분 단위 배열 3개(`chats`/`people`/`orders`)가 들어 있다. 리포트
5장의 시계열 차트가 이걸 그대로 쓴다.

**채팅과 주문을 같은 시간축에 겹쳐 그릴 것.** 원 사례에서 채팅은 20분 뒤 바닥인데
주문은 끝까지 꾸준했다. 결론이 "긴 방송이 무의미하다"에서 **"채팅이 죽은 채로 팔리고
있다 — 라이브의 무기를 5시간 놀린다"** 로 바뀌었다. 이 반전이 처방 4번의 근거다.

## 조용히 틀리는 지점 — 채팅 시각 파싱

`videoOffsetTimeMsec` 은 yt-dlp 버전에 따라 세 곳 중 하나에 실린다
(`replayChatItemAction` 안 / 최상위 / 액션). 못 읽으면 **모든 채팅이 첫 버킷으로
몰려** 첫20분 집중도가 100%, 죽은 구간이 90%대로 나온다. 오류 없이 그럴듯한
숫자가 나오는 게 위험하다.

`analyze_chat.py` 는 세 위치를 순서대로 보고, 하나도 못 찾으면 경고를 찍고
`chats_without_timestamp` 에 건수를 남긴다. **첫 회차에서는 첫20분 집중도가
100%가 아닌지 반드시 눈으로 확인할 것.**

방송 시작 전 대기 채팅은 음수 오프셋으로 들어오며 오프닝 구간에 합산된다
(`pre_show_chats` 에 건수가 남는다).

## 또 하나의 조용한 실패 — 파싱된 0 과 못 잰 null

상품코드를 하나도 못 뽑으면 `top3_share_pct` 는 **0 이 아니라 `null`** 이 된다.
0 은 "상위 3품목 점유율 0% = 완벽하게 분산됨"으로 읽혀 스코어카드 C2 에 **만점**을
주기 때문이다 — 파싱 실패가 좋은 점수로 둔갑한다. 같은 이유로 주문·구매자·상품을
못 뽑으면 스크립트가 경고를 찍는다. 경고가 뜨면 정규식부터 맞춘 뒤 진행한다.

## 교차 검증 — 반드시 한다

1. **회차 하나를 눈으로 대조** — 유튜브에서 리플레이를 켜고 주문봇 메시지를 직접 세어
   스크립트 출력과 맞는지 본다
2. **조회수 순위 vs 전환 순위 상관** — `make_measures.py` 가 자동 계산한다.
   음의 상관이면 "밀어주는 콘텐츠와 팔리는 콘텐츠가 반대"라는 2장 헤드라인이 성립한다
3. **오차 방향을 적는다** — 동명이인 병합 시 구매자 과소 집계(전환율은 실제보다 높음),
   최신 회차 조회수는 아직 증가 중(전환율이 실제보다 높게 잡힘). 방향이 반대라 상쇄되나
   크기는 알 수 없다고 리포트에 쓴다
